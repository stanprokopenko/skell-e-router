## What was proved

The Jev retake pass is step 1 of the design in `docs/superpowers/specs/2026-09-20-jev-roughcut-design.md` (skell-e-router). Given the production Retakes module's groups, Jev answers two questions per group: which take the editor keeps (a choice over the takes) and whether the group is a real retake at all (a yes/no). Code rules: a group with real-probability under 0.5 is not a retake and nothing is cut; otherwise the top take wins, except that when the top take's probability is within 0.15 of the last take's, the last take wins (Stan's rule: identical takes, keep the later one). On the 18 benchmark episodes this cut 186 losers of which the editor had kept only 20, and it beat the module's own last-take rule on the held-out episodes (`docs/jev-real/roughcut-jev-heldout.md`). It runs in 0.2 to 0.8 s per episode at concurrency 8 and costs well under a cent.

Exact prompt text: `scripts/jev_real/roughcut_jev_prompts.py` in skell-e-router, the retake questions under version v3 (they are unchanged since v1). The state shape and batching (up to 6 groups per request, each with the takes in spoken order and five sentences of context before and after, removed ums stripped) is in the `retake` pass of `scripts/jev_real/roughcut_jev.py`. Copy the prompt text verbatim; do not paraphrase it, Jev is sensitive to wording.

## Task 2: the AI pick button

Today the button is a disabled placeholder ("AI auto-pick, soon") in `RetakeReviewPanel.tsx`, and the retake group entries already carry a `picked_by: 'user' | 'ai'` field with a comment reserving confidence, reason and model fields for exactly this. The server hardcodes `picked_by: "user"` in `routers/retakes.py`. Real picks flow through `selectBestTake` as one undo-entry command batch and `POST /retakes/winner`; losers stay disabled on the timeline until "Remove unused takes". Scout notes give the lines.

Build it as:

1. Server endpoint, for example `POST /retakes/ai-pick` taking the media id. It reads the current retake groups and sentence texts, renders the state exactly as the benchmark pass does (takes in spoken order, five sentences of context either side; skip the um stripping unless the um sidecar is already available for that media, it is not required), batches up to 6 groups per request, and calls Jev through a new `call_classify` wrapper in `llm_router.py` (a test blocks importing `skell_e_router` anywhere else). Use `skell_e_router.classify("jev-1.13.0", state, questions, timeout=...)` with `config=None` so the router reads `TYPESAFE_API_KEY` from the environment, which is where the preferences layer already puts keys; do not pass an empty config dict, the router treats config as either/or with the environment and raises. Run the batches with a small thread pool and retry a failed request up to three times with 0.5 s and 1.5 s backoff; the benchmark saw bare provider errors on a few percent of requests. Apply the code rules above and return per group: winner sentence id, `real` probability, per-take probabilities, and whether the group was vetoed.
2. Client: enable the button when the TypeSafe key is set (the renderer sees `isSet` and `last4` only). On click, call the endpoint, then apply the winners through the existing `selectBestTake` path as one undo batch so a single undo reverts the whole AI pass, with `picked_by: 'ai'` and the confidence stored. For vetoed groups the proven behaviour is "keep every take"; apply that and mark the group visibly as "AI: not a retake" so the user can override. Show a compact result line ("Jev picked 41 groups, left 7 as not retakes, 0.6 s") rather than a modal. The user keeps editing as before.
3. Preferences: add a TypeSafe key row. The scout notes list the six mirrored places a key name must appear, the Electron `safeStorage` file, and the two delivery paths to Python (env at spawn, or live push through `POST /preferences/api-keys` which sets `os.environ`). Follow the existing rows exactly.
