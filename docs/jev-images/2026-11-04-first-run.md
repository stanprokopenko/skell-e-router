## Router change

Version 3.42.0 adds `classify(..., assets=...)`. Each image uses an opaque placeholder and an object containing `type`, `format` and `data_base64`. The router sends TypeSafe's image preview header when assets are present. It preserves the existing text request, retries, response validation and controlled error handling. Invalid envelopes fail before transport. The caller resizes images; TypeSafe validates image bytes and model access.

Image responses return `cost=None`. The published text token rate does not establish image pricing. Keeping this inside the router gives later consumers one tested calling path rather than separate HTTP implementations.

Source and tests are `skell_e_router/classification.py` and `tests/test_classification.py`. The API reference includes an example. No classification aliases were changed, and no installed shared Python package was upgraded.

Verification: `python -m pytest tests/test_classification.py -q` passed all 86 tests. `python -m pytest tests -q` passed all 1,116 tests and 17 subtests. An independent Astra review found no high or medium issues and separately passed the classification suite. These checks verify the implementation and simulated HTTP contract, not live image inference.
